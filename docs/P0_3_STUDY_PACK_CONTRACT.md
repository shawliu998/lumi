# Lumi P0.3 Study Pack contract

Status: **frozen implementation contract**

P0.3 turns learner-supplied local material into a small, cited practice pack.
It is an independent content/artifact domain. Importing, generating, reviewing,
publishing, or practising a Study Pack cannot write KT, the misconception
dossier, TodayPlan, or ReviewSchedule.

## Bounded scope

Accepted inputs:

- pasted UTF-8 text;
- a PDF whose text layer can be extracted locally.

P0.3 does not implement OCR, scanned-document recognition, URL or web crawling,
audio/video/image understanding, encrypted PDFs, multi-document synthesis,
table/image semantic reconstruction, cloud upload, or an implicit model call.
The client supplies bytes selected by the learner or pasted text; the service
does not accept an arbitrary local path.

One frozen source version may produce:

- exactly one cited one-page note;
- three to five cited knowledge cards;
- exactly three deterministically scored practice items;
- unconfirmed candidate skill links;
- exactly one pack-local review artifact.

The initial generator is `extractive-local@1`: it uses source-grounded excerpts
and deterministic cloze/exact-answer transformations. A model may later propose
a draft, but it must pass the same deterministic verifier and may not publish.

## Authority and isolation

- `StudyPackStore` owns Study Pack state in independent SQLite tables and a
  hash-chained event stream.
- Source bytes, normalized text, source versions, citation spans, published
  artifacts, verifier decisions, and command receipts are authoritative
  structured records.
- The general learning trace stores only opaque references and redacted result
  summaries. Raw source text and pre-attempt answer keys never enter general
  trace, errors, logs, or release reports.
- Candidate skill links always use `status=unconfirmed_candidate`. They cannot
  write a skill identifier unless it resolves against a versioned taxonomy
  snapshot, and they never write mastery.
- Study Pack item attempts use
  `evidence_origin=human_local_interactive` and
  `activity_kind=within_pack_practice`, but remain outside the P0.1/P0.2
  mastery, dossier, and scheduling projections.
- The release harness uses a private application-construction setting
  `evidence_origin=evaluation_fixture` in an automatically deleted database.
  That origin is not accepted from an HTTP body, cannot be relabelled as a
  learner attempt, and is never eligible for product learner projections. The
  frozen-sidecar harness maps the exact private process environment
  `LUMI_INTERNAL_STUDY_PACK_ATTEMPT_ORIGIN=evaluation_fixture` to that constructor;
  the Lumi app never sets it, and any other explicit value fails closed.

## Identifiers and commands

Public persistent entity IDs are generated by the service from 20 random bytes
and encoded as a type prefix plus 40 `A-P` characters. The client cannot submit
pack, document, span, artifact, verifier, or attempt IDs. Titles and filenames
are private metadata, never identifiers.

All public mutations require an opaque `c_` command ID, an exact
`expected_version` after creation, database-level compare-and-swap, a durable
idempotency receipt, closed request objects, and fail-closed conflict handling.
Phone, national-ID, UUID, semantic, email, path, and secret/token-shaped IDs are
rejected before any write.

## Source model

`SourceDocument` records:

- opaque document ID and monotonic source version;
- `input_kind=pasted_text|text_pdf` and media type;
- original-byte and normalized-text SHA-256 hashes;
- byte, page/section, and extracted-code-point counts;
- parser and normalization names plus exact versions;
- extraction state and stable warning/reason codes;
- private local source BLOB and normalized text.

Normalization is Unicode NFC plus canonical newline conversion. It does not
collapse other whitespace. PDF segments are one-based pages; pasted-text
segments are one-based sections split at blank-line boundaries. Citation
offsets are half-open Unicode code-point offsets into the normalized segment.

Every `SourceSpan` binds document ID, source version/hash, locator kind/index,
start/end offsets, and a SHA-256 of the exact slice. Resolution must re-slice the
frozen source and verify the hash; stored excerpt text is not trusted.

## Pack and artifact lifecycle

Pack lifecycle:

```text
draft -> review -> published
            \-> quarantined
```

- A source version and a published artifact version are immutable. Revision
  creates a new version.
- The service, not the client, computes source hashes, generator metadata,
  answer keys, verifier decisions, lifecycle, and skill-link status.
- `request_review` runs every verifier and appends one decision per artifact.
- `publish` is atomic and is allowed only when the current artifact set has a
  complete accepted review for the exact content digests.
- A quarantined artifact cannot be relabelled published. A new proposal version
  must be created from the frozen source.
- Draft, review, and quarantined artifacts cannot launch.

Required artifact types are closed:

- `study_pack.one_page_notes`;
- `study_pack.knowledge_card`;
- `study_pack.practice_item`;
- `study_pack.review_task`.

Every note claim, card answer, practice answer/explanation, and review-task
instruction has `{field_pointer, span_ref}` citations. Practice items support
only `cloze_exact_v1` and `normalized_exact_v1` in P0.3, so saved answers and
scores can be recomputed deterministically.

## Public API

All endpoints are loopback JSON APIs:

- `POST /v1/study-packs`
  - accepts `title`, `command_id`, and exactly one source union:
    `{kind:"pasted_text",text}` or `{kind:"text_pdf",pdf_base64}`;
- `GET /v1/study-packs`;
- `GET /v1/study-packs/{pack_id}`;
- `POST /v1/study-packs/{pack_id}/commands`
  - accepts only `request_review` or `publish` plus version/command fields;
- `GET /v1/study-packs/{pack_id}/citations/{span_id}`;
- `GET /v1/study-packs/{pack_id}/replay`;
- `GET /v1/study-pack-items/{artifact_id}/launch`;
- `POST /v1/study-pack-items/{artifact_id}/attempts`.

The launch response never contains an answer key, answer citation, verifier
private payload, or raw source outside the question prompt. The attempt response
may reveal deterministic score, answer, explanation, and cited source context
only after a real learner answer is accepted.

`GET /v1/study-packs/{pack_id}` includes chronological `attempt_history` only
for persisted `human_local_interactive` attempts. Before the first accepted
human answer it is an empty array and discloses no practice answer. Each history
entry re-joins the exact immutable artifact id/version and re-verifies the
artifact and learner-answer digests, scorer, saved score, and every source
slice/hash before returning the prompt, learner answer, correct answer,
explanation, and cited context. Evaluation-fixture attempts are always excluded;
any integrity mismatch fails the projection closed. History is chronological
evidence, not a claimed learning “round” because P0.3 has no session identifier.

This is a direct-key disclosure boundary, not a cheating-prevention claim: the
learner owns the frozen source, and published notes or knowledge cards may
contain the same source statement. While an item is unanswered, the client must
show the isolated launch projection and must not render pack notes, card answers,
or citation context beside the active prompt.

Fixed resource-protection limits for v1 are engineering limits, not learning
policy: pasted text <= 512 KiB UTF-8; decoded PDF <= 8 MiB; <= 120 pages;
<= 250,000 normalized code points; parser deadline <= 10 seconds. The Study Pack
route may have a separate <= 12 MiB JSON body limit without expanding the
existing default API body limit.

Stable failures include `invalid_source_body`, `source_too_large`,
`pdf_parse_failed`, `pdf_encrypted_unsupported`,
`pdf_text_unavailable_ocr_required`, `source_insufficient_for_pack`,
`citation_unresolved`, `artifact_unsupported`, `artifact_quarantined`,
`artifact_not_published`, `stale_version`, `command_conflict`, and
`invalid_transition`. Persisted history integrity failures use
`attempt_history_invalid`. Parse/input failures leave no document, artifact, event,
or learning-state write. A successfully frozen source whose generation is
insufficient may leave a quarantined pack with a bounded reason code.

## Deterministic verification

Review must prove:

- closed schemas and required artifact counts;
- immutable source version/hash and resolvable locator/offset/slice hash;
- complete citations for every required claim, answer, and explanation;
- deterministic recomputation of extractive transformations and scorers;
- no answer leakage from prompt/options or launch response;
- stable artifact content digest and generator/verifier provenance;
- every candidate skill remains unconfirmed;
- generator/verifier disagreement quarantines rather than last-write-wins;
- no network, OCR, web, protected-repository, KT, dossier, TodayPlan, or
  ReviewSchedule write capability.

## Release gate

The `study_pack` release gate uses one Chinese pasted-text fixture and one real
text-bearing PDF fixture through the production loopback router and a temporary
database. For both sources it must prove:

1. `create -> request_review -> publish -> resolve citation -> launch ->
   explicitly non-learner TEST INPUT answer -> replay` works after restart,
   while the ordinary product path remains `human_local_interactive`.
2. Artifact counts, schemas, hashes, page/section citations, scorers, CAS,
   receipts, and hash-chain replay all verify.
3. Every published required claim/answer has a resolvable citation and every
   saved score can be recomputed.
4. Draft/review/quarantined artifacts and answer keys remain unlaunchable or
   invisible before a real answer.
5. Malformed, empty, encrypted, scanned, oversized, over-page, over-character,
   timeout, unknown-field, invalid-base64, sensitive-ID, stale-version, and
   concurrent-publish cases fail closed.
6. KT, misconception, TodayPlan, and ReviewSchedule storage/projection digests
   are unchanged across import, publish, practice, and replay.
7. General trace and saved evaluation evidence contain no raw source text,
   pre-attempt answer key, secret, or protected/local absolute path.
8. The packaged Lumi.app uses the same parser and real sidecar path; connected,
   empty, offline, parse error, quarantine, published, narrow, and completed UI
   states pass visual QA against the existing Khanmigo-grounded Lumi baseline.
9. The production Shenlun repository remains clean at the frozen HEAD.

P0.3 cannot be called complete from schema/unit tests alone. The real HTTP flow,
packaged sidecar, Mac app, release evidence, and read-only boundary must all pass.
